# 教育知识库项目 · 需求评审与修改建议

> 评审对象：用户提供的《教育知识库项目实战需求说明》
> 评审基准：模板项目 `atguigu-shopkeeper/knowledge` 的实际能力 + 已搭建的 `atguigu_edu_keeper` 整体框架
> 结论先行：需求方向与模板架构（导入/查询双 LangGraph + Milvus/Mongo/MinIO）**总体匹配**，但核心对象模型
> 必须从模板的「单一商品名 item_name」升级为「**内容类型 × 多维归属元数据**」，否则课程/题库/引用等诉求无法落地。

---

## 一、总体判断

1. **导入链路可复用**：PDF/讲义文档 → MinerU → MD → 图片(VLM) → 标题分块 → 向量 → Milvus 的链路，
   完全支撑「课程资料/项目文档/教学讲义」类内容。
2. **问答链路可复用**：HyDE/混合检索/RRF/重排/MCP 补全/SSE 输出 支撑「知识问答 + 流式 + 引用」。
3. **最大风险点**：模板是一个「一个文档 = 一个商品名」的扁平模型；需求要求「课程→项目/章节→题目」的
   **多维目录化**内容与**结构化题目检索**，这是模板没有的，也是需求文档目前表述最含糊、最需要修改的部分。
4. 需求中的「课程列表/课程详情/章节树/先修要求」属于**结构化目录信息**，不适合只靠向量切片检索，
   建议采用「MongoDB 结构化管理 + Milvus 向量检索」双存储策略，需求文档需明确这一点。

## 二、P0：必须修改/明确的点

### 2.1 元数据维度不足（最核心）
- **原文问题**：第 5 条字段表有 课程名/项目名/章节名/题库名/题目编码/题型/来源文件名，但全文搜索条件还有「**知识点**」，
  且没有说明这些字段与「一条内容」的关系（文件级？切片级？逐题级？）。
- **建议**：
  1. 增加字段：`知识点/标签(可选)`、`来源URL/链接`、`题目难度(可选)`、`题目所属课程`。
  2. 明确**元数据继承规则**：文件级默认（课程名/项目名/题库名/来源文件名由导入时确定）→ 切片级覆盖（章节名由 MD 标题层级推导）→ 条目级覆盖（题目自带编码/题型/选项）。
  3. 明确**必填矩阵**：不同内容类型可填字段不同（见下文第四节），例如「课程介绍」不需要题库名，「题目」必填题型与编码、可无项目名。

### 2.2 内容类型路由缺失
- **原文问题**：需求把 课程介绍/文档片段/项目资料/题目 混在同一套“检索”里，但它们的结构差异很大：
  题目是结构化记录（题型/选项/答案/解析，答案与解析甚至不应被直接全文检索返回），课程介绍是整段结构化介绍。
- **建议**：在第 2 节增加「**导入类型路由**」：
  - 文档/讲义类 → 走 MinerU 向量链路；
  - 题目/题库类 → 走**结构化解析**（表格/列表 → 一条一题 → 结构化字段入 Milvus 标量列 + 正文入向量列），
    检索时按 题型过滤 + 知识点向量召回；
  - 课程介绍/课程目录类 → 走**课程档案**（建议新增一种导入物：每门课的课程档案 JSON/Markdown，
    含 简介/适用人群/先修/章节树/项目清单），结构化存 MongoDB，向量化辅助召回。

### 2.3 题目检索的返回口径与答案脱敏
- **原文问题**：4.4 要求返回「答案与解析」，但若问答链路把题目切片当普通上下文喂给 LLM 再生成，
  极易把答案解析原样泄露给学员（考题场景）且无法保证题型/选项字段结构化返回。
- **建议**：明确两种形态并分场景：
  1. 助教/管理侧「题库检索」→ 结构化返回题目全文（含答案解析）；
  2. 学员侧「题目问答」→ 按 题型返回题干/选项/解析指引，**答案是否展示由场景决定**（可在需求中加一个开关字段 `show_answer`）。
  同时要求回答附带 `题目编码 + 题库名 + 题型` 引用。

### 2.4 文件格式范围未定义
- **原文问题**：提到「课程资料、项目文档、教学讲义、题库与题目」，但没说是什么格式。
  模板链路只原生支持 PDF → MD（及 MD 直传）；Word/PPT/Excel 题库需要额外解析。
- **建议**：在第 2 节补一张「格式矩阵」，例如：
  - V1：PDF、Markdown、Word(docx，先转 PDF 或 python-docx 直读)；
  - V2：PPT(转 PDF)、Excel 题库（结构化解析模板，建议规定题库 Excel 列名规范）；
  - 明确 MinerU 无法直接吃 docx/pptx，需先转 PDF。

### 2.5 “每条内容”与“切片”粒度冲突
- **原文问题**：第 5 条「知识库中的每条内容建议包含以下字段」——题库可按“一条=一题”，
  但长文档按“一条=整个文档”会无法切片入库。
- **建议**：将第 5 条改名为「**知识条目(Entry)元数据规范**」，并补充说明：
  文档按章节拆为切片(Chunk)入库、每题作为独立条目入库、课程介绍整体作为条目入库；
  所有切片/条目统一携带第 5 条元数据（通过 2.1 的继承规则生成）。

### 2.6 课程详情/章节树的结构化来源缺失
- **原文问题**：4.1/4.2 要求返回“章节结构、先修要求、项目实战内容”，但没说明这些数据从哪来、
  谁维护。向量库里的“课程简介文档”无法可靠生成结构化章节树。
- **建议**：新增「**课程档案导入**」（见 2.2），并让教学运营按模板维护；
  若不想新增类型，则需求须说明“章节结构以文档目录解析结果为准、先修要求以课程简介文档人工维护为准”。

## 三、P1：建议补充/明确的点

1. **交互与页面范围**：模板只有导入页，无问答页。需明确 V1 交付界面：两个前端页（导入页 + 问答页/检索页），
   还是只交付 API + 测试？4.x 场景里的「返回课程列表/题目列表」建议在问答页以结构化卡片渲染，
   需要需求里写明是“对话式返回列表”还是“独立检索列表页”。
2. **多轮对话语义**：历史管理范围（仅知识问答，还是检索也算）、会话(session)的生命周期、
   历史存储（模板已有 MongoDB 计划，够用，需写明保留条数/上限）。
3. **SSE/状态事件定义**：可让第 2 节补一句「导入任务状态与问答流式均通过 SSE 推送」，
   与模板 task_util/sse_util 对齐。
4. **引用溯源格式**：建议定义统一引用格式，如 `[来源:课程=xx 章节=xx 文件=xx]`/`[题:题库=xx 编码=xx]`，
   并注明“引用来自切片标量元数据，禁止 LLM 编造”。
5. **质量验收方式**：“尽量准确”无法验收。建议后续补「评测集：N 条典型问题 + 期望引用 + 人工打分」，
   至少先给可操作的验收：检索 Top-K 命中率 / 引用字段非空率 / 错误不中断服务。
6. **异常处理边界**：明确“导入失败单文件失败不影响服务、任务标记失败并可查原因”，
   与模板 BackgroundTasks + 任务容器机制对齐。
7. **扩展方向措辞**：视频/多模态/多租户等目前只是方向，建议在需求中加一句
   “上述扩展不进入 V1 验收，但字段模型需预留：来源链接/时间轴/权限租户字段可空”。
8. **角色与权限**：V1 无登录则角色只是“使用场景”说明；若要做角色，需另加权限模块需求。
   建议明确 V1 不做鉴权，角色仅用于描述使用方。

## 四、建议的数据模型草案（供需求与代码同步）

### 4.1 内容类型枚举（content_type）
| 值 | 含义 | 导入走哪条链 |
| --- | --- | --- |
| `course_intro` | 课程介绍/档案(目录树/先修) | 课程档案结构化(Mongo) + 向量 |
| `doc_chunk` | 课程/项目文档切片 | 文档向量链路(MinerU→分块→Milvus) |
| `project_material` | 项目资料 | 文档向量链路 |
| `question` | 题目 | 结构化解析(一条一题) |

### 4.2 条目/切片标量元数据（写入 Milvus 的标量列 + MongoDB）
| 字段 | 类型 | course_intro | doc_chunk | project_material | question |
| --- | --- | --- | --- | --- | --- |
| content_type | str | 必填 | 必填 | 必填 | 必填 |
| course_name | str | 必填 | 必填(继承) | 必填(继承) | 必填/可选 |
| project_name | str | 选 | 可选 | 必填 | 选 |
| chapter_name | str | 目录树 | 必填(标题推导) | 可选 | 选 |
| bank_name | str | – | – | – | 必填 |
| question_code | str | – | – | – | 必填 |
| question_type | str(枚举) | – | – | – | 必填 |
| show_answer | bool | – | – | – | 必填(脱敏开关) |
| knowledge_point | str(标签, 可多值) | 选 | 选 | 选 | 必填/选 |
| source_file | str | 必填 | 必填 | 必填 | 必填 |
| source_link | str | 选 | 选 | 选 | 选 |

> 注：Milvus 集合需在**建集前**确定全部标量列（模板 `import_milvus` 的 `_MilvusSchemaBuilder` 依赖固定 dim 与字段），
> 因此字段模型要先定稿再写导入节点。

### 4.3 导入状态图状态字段增量（ImportGraphState 建议新增）
```
content_type / course_name / project_name / bank_name(识别节点输出)
question 结构化条目列表 questions(List[dict])   ← 题目型导入的中间产物
章节名(由 md 标题层级推导,挂在每个 chunk 上)
```
> 模板的 `item_name` 建议升级/替换为 `metadata`(dict)，`item_name_recognition` →
> 「内容归属识别」(识别 content_type + 课程名/项目名/题库名)，问答侧 `item_name_confirm` → 「元数据实体对齐」。

## 七、V1 简化决策（已确认：一切从简，先实现功能）

> 用户答复：一切从简、先把功能跑通。下列决策覆盖第六节全部问题，作为 V1 实现基线，
> 后续如需求升级再放宽。

| 决策点 | V1 从简方案 |
| --- | --- |
| 导入格式 | 只支持 **PDF / Markdown**（模板原生链路）；Word/PPT/Excel 题库暂不做结构化解析，题目作为文档内容入库 |
| 课程档案 | **不新增**“课程档案 JSON/Markdown”导入物；课程介绍按普通文档导入，章节结构由 MD 标题层级解析（文档分块天然产生） |
| 题目答案 | 不做 show_answer 脱敏分层，题库/题目检索与问答直接返回内容（含答案与解析） |
| 界面范围 | 先做 **导入页 + 问答接口(SSE 流式) + 简单问答页**；不单独做课程/题库检索列表页（列表信息由对话返回） |
| 知识点字段 | **不新增**必填“知识点”标量；知识点检索依赖向量语义命中 + 章节/标题文本 |
| 引用与验收 | 保留“引用来源信息”（课程名/章节名/文件名等标量随切片输出、回答附引用）；不做正式评测集 |
| 异常处理 | 单文件导入失败标记任务失败、不影响服务整体（任务容器记录失败节点与原因） |
| 元数据 | 平铺到切片/条目：`content_type + 课程名/项目名/章节名(标题推导)/来源文件名`；题目内容复用同一结构，`题库名/题目编码/题型` 由文档命名与内容中提取(尽力而为，不单独建结构化模型) |

> 对应实现方式：**逐模块移植模板实现并适配平铺导入**（去掉 `knowledge.` 前缀），
> 按 README 开发路线 1→9 推进；先打通「导入链路」，再打通「问答链路」。
